================================================================================
          COMPLETE STEP-BY-STEP DEPLOYMENT GUIDE (100% FREE)
================================================================================

This project is a Fullstack Web Application consisting of:
  1. Frontend Client: React (built with Vite)
  2. Backend Server: Node.js & Express
  3. Database: MongoDB Atlas (Cloud Database)

To deploy this fullstack app for free, you have two excellent methods:
  - METHOD A (Highly Recommended): Frontend on Vercel (Free) + Backend on Koyeb/Render (Free)
  - METHOD B: Entire application (Frontend + Backend) on Vercel using Serverless Functions

Follow the detailed steps below for your preferred method.

--------------------------------------------------------------------------------
PREREQUISITE: DATABASE SETUP (COMMON TO BOTH METHODS)
--------------------------------------------------------------------------------
Since your database (MongoDB Atlas) is in the cloud, cloud servers need permission to connect to it.

1. Go to MongoDB Atlas (https://cloud.mongodb.com/) and log in.
2. In the left sidebar, click on "Network Access" under the Security section.
3. Click "Add IP Address".
4. Select "Allow Access from Anywhere" (this adds the IP address `0.0.0.0/0`).
   - Note: This is required because Vercel/Koyeb/Render use dynamic IP addresses that change constantly.
5. Click "Confirm".
6. Copy your MongoDB Connection String from the ".env" file. You will need it during deployment.

================================================================================
METHOD A: FRONTEND ON VERCEL & BACKEND ON KOYEB / RENDER (RECOMMENDED)
================================================================================
Why this is recommended: Vercel is designed for fast, static frontend websites. Express servers are designed to be persistent processes, which run perfectly on Koyeb or Render's free tiers.

-----------------------------------------
STEP A1: Deploy the Backend to Koyeb (Easiest & Fastest Free Tier)
-----------------------------------------
Koyeb provides a fast, modern free tier for Node.js servers:
1. Push your code to a GitHub repository (keep it public or private).
2. Go to Koyeb (https://www.koyeb.com/) and create a free account.
3. Click "Create Service" or "Deploy".
4. Select "GitHub" as the deployment method.
5. Choose your repository.
6. Configure the deployment settings:
   - Work Directory: `server` (This tells Koyeb to run the backend server)
   - Build Command: `npm install`
   - Run Command: `npm start`
   - Under "Environment Variables", click "Add Variable":
     * Key: `MONGO_URI` | Value: [Your MongoDB connection string from .env]
     * Key: `PORT` | Value: `8080` (or leave it to Koyeb to bind automatically)
7. Click "Deploy".
8. Once deployed, Koyeb will give you a public URL (e.g., `https://your-app-name.koyeb.app`). Copy this URL.

*Alternative Backend Host (Render):*
If you prefer Render (https://render.com/):
1. Sign up and click "New" -> "Web Service".
2. Connect your GitHub repository.
3. Set the Root Directory to `server`.
4. Set Build Command to `npm install` and Start Command to `node index.js`.
5. Under Environment Variables, add `MONGO_URI` with your connection string.
6. Click Deploy. Copy your Render URL.

-----------------------------------------
STEP A2: Update Frontend API URL to Point to Your Deployed Backend
-----------------------------------------
Currently, your frontend (`src/App.jsx` line 3) points to `localhost:5000`:
  `const API_URL = 'http://localhost:5000/api';`

To make it dynamic and ready for production, change that line to:
  `const API_URL = import.meta.env.VITE_API_URL || 'http://localhost:5000/api';`

This tells Vite to use the environment variable `VITE_API_URL` when deployed, but fallback to localhost during local development.

-----------------------------------------
STEP A3: Deploy the Frontend to Vercel
-----------------------------------------
1. Go to Vercel (https://vercel.com/) and sign up with your GitHub account.
2. Click "Add New" -> "Project".
3. Import your GitHub repository.
4. Configure the project:
   - Framework Preset: Select "Vite"
   - Root Directory: Choose `./` (the root directory of your project)
   - Build and Output Settings:
     * Build Command: `npm run build`
     * Output Directory: `dist` (default for Vite)
   - Under "Environment Variables", add:
     * Key: `VITE_API_URL` | Value: `https://your-backend-url.koyeb.app/api` (the URL from STEP A1)
5. Click "Deploy".
6. Your frontend is now live! Vercel will give you a domain (e.g., `https://your-project.vercel.app`).

-----------------------------------------
STEP A4: Allow Your Frontend Domain in CORS (Backend)
-----------------------------------------
Your backend server (`server/index.js`) controls which frontends are allowed to make requests.
Look at lines 20-27 of `server/index.js`:
```javascript
app.use(cors({
  origin: [
    "https://daily-learning-journal-beryl.vercel.app",
    "http://localhost:5000",
    "http://localhost:5173"
  ],
  credentials: true
}));
```
Make sure to add your new Vercel frontend URL to this array, commit the changes, and push them to GitHub. The backend will automatically redeploy and allow requests!


================================================================================
METHOD B: ENTIRE APP (FRONTEND + BACKEND) ON VERCEL (ALL-IN-ONE)
================================================================================
If you want to host both frontend and backend on Vercel without using separate services, you can configure Vercel to treat the Express backend as a Vercel Serverless Function.

-----------------------------------------
STEP B1: Prepare the Express Server for Vercel
-----------------------------------------
1. Serverless platforms require your Express app to be exported rather than constantly listening.
   Modify `server/index.js` so `app.listen()` only runs in development:

   Replace the listen block:
   ```javascript
   app.listen(PORT, () => {
     console.log(`Server running on port ${PORT}`);
   });
   ```
   With:
   ```javascript
   if (process.env.NODE_ENV !== 'production') {
     app.listen(PORT, () => {
       console.log(`Server running on port ${PORT}`);
     });
   }
   export default app;
   ```

2. Make sure you have `export default app;` at the bottom of `server/index.js`.

-----------------------------------------
STEP B2: Create `vercel.json` Configuration
-----------------------------------------
Create a file named `vercel.json` in the root of your project directory with the following content:
```json
{
  "version": 2,
  "builds": [
    {
      "src": "package.json",
      "use": "@vercel/static-build"
    },
    {
      "src": "server/index.js",
      "use": "@vercel/node"
    }
  ],
  "routes": [
    {
      "src": "/api/(.*)",
      "dest": "server/index.js"
    },
    {
      "src": "/(.*)",
      "dest": "/$1"
    }
  ]
}
```
This tells Vercel:
  - To build the frontend using your root `package.json`'s build script (Vite).
  - To treat `server/index.js` as a Node serverless function.
  - To route all frontend requests starting with `/api` directly to your Express server.

-----------------------------------------
STEP B3: Make API URL Relative in Frontend
-----------------------------------------
Since Vercel will host both the frontend and the backend under the exact same domain name, you don't need a full URL with `http://localhost:5000`. You can use a relative route!

Modify `src/App.jsx` line 3:
  `const API_URL = '/api';`

This prevents CORS errors and makes frontend-to-backend communication completely seamless.

-----------------------------------------
STEP B4: Deploy to Vercel
-----------------------------------------
1. Push all your changes to GitHub (including the new `vercel.json`).
2. Go to Vercel and import your repository.
3. Do not change any root directories or build configurations.
4. Under "Environment Variables", add:
   - Key: `MONGO_URI` | Value: [Your MongoDB connection string]
5. Click "Deploy".
6. Your application will build, configure the serverless function, and host the entire fullstack app under a single free Vercel domain!

================================================================================
TROUBLESHOOTING TIPS
================================================================================
- **Database Connection Failure**: If your logs show MongoDB connection errors, double check that your MongoDB IP whitelist has `0.0.0.0/0` enabled (Step 1).
- **CORS Errors**: If you get CORS errors in Method A, verify that the backend's allowed origins list in `server/index.js` exactly matches your Vercel frontend domain (with `https://` and without a trailing slash).
- **Serverless Timeout**: Vercel Serverless Functions on the free plan have a 4.5-second execution limit. If your database queries take too long or the database is cold, Vercel might return a `504 Gateway Timeout` error. This is why Method A (Koyeb/Render) is generally preferred for persistent servers.
